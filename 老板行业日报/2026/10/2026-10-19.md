## [vLLM v0.32.0 发布：814 个提交，低精度 KV 缓存与结构化决策 API 成亮点](https://github.com/vllm-project/vllm/releases/tag/v0.32.0) ⭐️ 8.0/10

vLLM 发布了 v0.32.0，该版本包含来自 363 位贡献者（其中 121 位是新人）的 814 个提交，核心亮点是新增的 \`POST /v1/systemone\` 结构化决策端点，可就结构化状态回答 \`choice\`、\`noul\` 和 \`score\` 三类问题；同时引入通用的 \`hf\` 工具调用与推理解析器（\`--tool-call-parser hf\`、\`--reasoning-parser hf\`），它们读取检查点自带的 \`response\_template\`，因此自带该模板的模型无需再编写模型专属解析器。该版本还把低精度 KV 缓存的支持范围大幅扩展：NVFP4 KV 缓存现已支持 SM8x、SM12x 与 SM90（含 SM12x 上的 XQA 解码），GLM-5.x 在 SM100 上默认使用 FP8 KV 缓存，ROCm 平台则新增了 4 位 \`ultraquant\_4bit\` KV 缓存。 vLLM 事实上已成为开源 LLM 推理引擎的标准，因此这些改动会直接影响到团队的模型部署与优化方式：通用 HF 解析器免去了按模型维护解析器的工作，而低精度 KV 缓存支持则降低了每个 rank 的显存占用，并在最新的 NVIDIA 与 AMD GPU 上提升吞吐量。对部署工程师而言，该版本给出的是具体、可用于决策的权衡数据，而非空泛的性能宣传。 性能声明都附带了明确的权衡条件：在 PR 的基准测试中，GLM-5.x 在 SM100 上默认启用 FP8 KV 缓存后，每个 rank 的 KV 显存减半，吞吐量提升 2.3–5.5%，但 TTFT 增加 7–11%；SM90 上的 \`fp8\_ds\_mla\` 让 GLM-5.3-Flash 的输出吞吐量最多提升 31%；ROCm 的 4 位缓存密度约为 FP8 的两倍。破坏性变更也不少：不再支持 Python 3.10，默认 CORS 来源被收紧，torch.compile 的序列并行与 AsyncTP pass 以及 cascade attention 被移除，\`max\_tokens\` 不再从上下文窗口中预留；安全方面修复了三个 GHSA 漏洞，涉及聊天模板资源耗尽和 P2P ZMQ 套接字耗尽。

github · khluu · 10月18日 06:50

**背景**: vLLM 是一个面向大语言模型的开源高吞吐推理服务引擎，其 KV 缓存保存已处理 token 的键/值张量，使生成时无需在每一步重算整个提示词——在长上下文和高并发场景下，这块缓存往往是 GPU 显存的主要占用者。将 KV 缓存量化为 FP8、NVFP4 等低精度格式（NVFP4 是专为 Blackwell 等 NVIDIA 新架构 GPU 设计的 4 位浮点格式）可以降低显存占用并提升算术吞吐。SM8x/SM90/SM100/SM12x 等标识指 NVIDIA GPU 架构代次，XQA 是面向 MQA/GQA 模型的优化注意力解码内核，而 vLLM 的结构化决策端点针对某个状态提出带类型的问题，并返回每个允许答案的概率，而非直接生成文本。

## [Google Research 开源递归智能体优化框架 Harness²](https://github.com/google-research/harness2) ⭐️ 8.0/10

Google Research 开源了 Harness²，这是一个采用 Apache 2.0 协议、通过两层相互关联的递归来优化 LLM 智能体的框架，且无需更新模型权重。据报道，它在 WorkBuddy-Bench 等基准上最高带来 11.5 分的提升，其中在权重冻结的情况下让 GLM-5 提升了 11.5 分；框架还支持并行与顺序两种递归模式，并内置了基准测试集成。 该框架提供了一种可立即使用、许可证宽松的推理阶段性能提升手段，绕开了微调或强化学习训练的成本与复杂度。由于被优化的是执行框架而非模型本身，它有潜力跨不同基座模型泛化，并成为智能体部署栈中的标准组件。 该优化作用于执行框架（即围绕模型的提示词、工具与控制循环），并从每一次改进过程中学习以指导后续的框架构建，因此收益无需改动模型权重即可获得。它是一个即插即用的组件，同时提供并行与顺序两种递归模式；主要数据来自腾讯面向编码智能体的 WorkBuddy-Bench，跨基准的泛化能力仍需独立验证。

telegram · zaihuapd · 10月18日 11:24

**背景**: 智能体“执行框架”（harness）指的是把一个基座模型变成可用智能体所需的外围组件：系统提示词、工具定义、重试逻辑以及“规划—执行—观察”循环。递归自我改进（RSI）指系统迭代地重写自身脚手架，但以往的工作往往高度依赖具体任务，难以迁移到新场景，这正是 Harness² 试图用两层相互关联的递归来弥合的问题。腾讯发布的 WorkBuddy-Bench 在 Code、Web、Office、Security 四个赛道中，用真实开发者、产品、测试、运维与安全任务来评测编码智能体，并把产出的补丁与工件对照测试套件打分。通常，要在这类基准上提升智能体得分需要微调权重或进行强化学习训练，成本高且与特定模型绑定。

## [Together AI 推出 HybridAgent：在潜空间推理，用文本行动](https://arxiv.org/abs/2610.18861) ⭐️ 7.0/10

来自斯坦福、Together AI、UIUC 和 Meta 的研究人员发布了 HybridAgent，这是一种 LLM 智能体架构，能在同一次生成过程中在潜空间推理与文本交互之间动态切换，只在需要行动或交流时才输出文本。该工作同时开源了 GitHub 代码、包含 14B 版本在内的 Hugging Face 模型合集，并在 arXiv 论文中给出了覆盖 11 个基准的评测结果。 显式的思维链推理缓慢且昂贵，因为每一步推理都必须以 token 形式输出；把思考压缩进隐藏状态，有望大幅降低智能体任务的推理成本与延迟。由于代码、权重和评测全部公开、可即时复现，它为智能体开发者社区在潜空间推理这一新兴方向上提供了一个具体的基线，而不只是一篇论文。 据相关报道，HybridAgent 在 11 个基准上降低了 token 消耗并加快了推理速度，但其给出的成本估算并未计入提示词和工具调用开销，因此实际节省可能更小。实际复现体验参差不齐：有评论者用 llama.cpp 加载 bartowski 的 8 位量化 14B 模型，在一个简单的对话加摘要任务中，模型反复输出雷同段落直至耗尽回合预算。

hackernews · allinonai · 10月18日 20:48 · [社区讨论](https://news.ycombinator.com/item?id=50145337)

**背景**: 传统的思维链（CoT）提示让模型“出声思考”，在给出答案前把每一步中间推理都写成普通 token；这虽然有效，却成倍放大了 token 数量、成本和延迟。潜空间推理则改为在模型的隐藏状态中完成多步推断——这些稠密向量有时被称为“潜 token”——从而完全跳过语言化这一步。HybridAgent 针对的是纯潜空间推理的明显短板：智能体仍必须以文本形式发出工具调用和消息才能与外部世界交互，因此该架构让模型在思考时保持潜模式，仅在执行动作时切换到文本模式。

## [Anthropic 起草前沿 AI 安全法案，拟由联邦法院裁定是否叫停模型发布](https://news.google.com/rss/articles/CBMiUkFVX3lxTFB5UEhHNVdjb3Z5eVlKM204eDNlM09XM09idHNFQ3RGVkRTRjMzUjEyeF9tLTI5RVVNUFZvUy0yUElBN2V5WGZWQmJCWDdtSFhNdkE?oc=5) ⭐️ 7.0/10

据报道，Anthropic 已向美国国会议员递交一份前沿 AI 安全法案草案：只有当模型可能造成超过 10 亿美元损失，或导致超过 50 人死亡或受伤时，政府才可以阻止其发布。草案还规定，由商务部注册的独立第三方评估机构定期评估实验室与模型，一旦发现生物武器、AI 网络攻击或失控风险，须在 72 小时内上报。 这标志着领先实验室主动参与塑造约束自身的规则，而较高的危害门槛加上法院裁定机制，实际上会锁定一个相对宽松的前沿模型发布制度。若获通过，它将确立联邦层面的基线，压过各州日益繁杂的 AI 立法拼图，并限制未来监管机构叫停模型部署的空间。 草案规定只有商务部可以下令叫停，最终由联邦法官裁定，其他美国机构被明确禁止发布停止令。草案设定的量化门槛——10 亿美元损失或 50 人以上伤亡——远高于目前大多数已记录的 AI 危害，而且据报道该文本目前尚无具名提案人、法案编号或时间表。
