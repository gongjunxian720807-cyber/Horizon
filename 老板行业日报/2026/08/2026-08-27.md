## [vLLM v0.28.0 发布，显著提升 Kimi-K3 与 DeepSeek V4 推理性能](https://github.com/vllm-project/vllm/releases/tag/v0.28.0) ⭐️ 9.0/10

vLLM v0.28.0 正式发布，包含来自 270 位贡献者的 584 次提交，重点针对 Kimi-K3 和 DeepSeek V4 推理进行性能优化。该版本新增了解码上下文并行（DCP）支持、融合 FlashKDA 内核、增强的 DSpark 推测解码，以及分层 KV 缓存卸载等功能。 作为应用最广泛的开源推理引擎之一，vLLM 的优化直接影响大规模 LLM 部署的推理成本和延迟。针对 Kimi-K3 和 DeepSeek V4 的改进表明，内核级优化与推测解码的进步正在重塑前沿模型推理服务的经济性。 值得注意的变化包括：Kimi-K3 的 DSpark 首词延迟（TTFT）改善约 60%，通过可选的共享专家分片每 GPU 节省约 17 GiB 显存，合并 all-gather 带来 1.5 至 3 倍的内核级加速。此外，max\_num\_batched\_tokens 提升至 16384，Mamba 模型默认启用前缀缓存，bitsandbytes 支持迁移为外置插件。

github · khluu · 8月26日 09:46

**背景**: vLLM 是一个开源的高吞吐量 LLM 推理与服务引擎，广泛用于生产环境。解码上下文并行（DCP）按序列维度将 KV 缓存分片到多张 GPU 上，从而提升长上下文吞吐；FlashKDA 是 Moonshot AI 基于 CUTLASS 的高性能 Kimi Delta Attention 内核。DSpark 是 DeepSeek 提出的推测解码框架，将并行生成与置信度调度的验证相结合，在保持输出逐字节一致的同时加速推理。

## [千问 3.8-Flash-Next：融合 N-gram 嵌入的高效 125B 大模型](https://qwen.ai/blog?id=qwen3.8-flash-next) ⭐️ 9.0/10

阿里巴巴千问团队发布了 Qwen3.8-Flash-Next，这是一个拥有 125B 参数主模型、51B N-gram 嵌入、每个 token 仅激活 6B 参数的新型大语言模型。用户报告称，90M 缓存输入仅花费 0.45 美元，表明其以极低成本实现了强大性能。 此次发布标志着向以内存换取计算效率的混合架构的重大转变，可能使前沿 AI 的部署成本大幅降低。同时，它也加剧了与 DeepSeek、Google Gemma 等其他开源权重模型的竞争。 该模型使用多哈希 N-gram 嵌入技术，这一技术曾在 DeepSeek 的 Engram 论文中探讨过；尽管总参数达 176B，但运行时仅激活 6B 参数。4-bit 量化版本可能超过 100GB，因此能否在 128GB 统一内存中运行尚不确定。

hackernews · tosh · 8月26日 12:52 · [社区讨论](https://news.ycombinator.com/item?id=49448210)

**背景**: N-gram 嵌入是一种用模式匹配查找表增强 Transformer 语言模型的技术，可减少常见 token 序列所需的计算量。最近一篇论文《Scaling Embeddings Outperforms Scaling Experts in Language Models》表明，在混合专家模型中扩展这些嵌入的效果优于增加专家参数。DeepSeek 的 Engram 和 Google Gemma 的轻量版本也采用了类似方法。
