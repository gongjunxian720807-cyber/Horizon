## [OpenAI 发布 GPT-6.1 Sol：接近 Astra 的智能，价格仅五分之一](https://openai.com/index/introducing-gpt-6-1-sol/) ⭐️ 8.0/10

OpenAI 发布了 GPT-6.1 Sol，这一升级版在 GPT-6 Sol 上线仅约七天后就将其取代，官方称其在智能体编程、计算机操作和专业任务上的智能水平接近 GPT-6 Astra，而输入输出价格仅为 Astra 标准价的大约五分之一。缓存输入价格低至每百万 token 0.10 美元，该模型已开始向 ChatGPT 的 Plus、Pro、Business、Enterprise 和 Edu 用户推送。 这次发布把竞争焦点从单纯的模型能力转向性价比：一个智能水平接近旗舰、但成本只有其零头的模型，会直接改变大规模运行智能体工作负载的经济账。它也对 Anthropic、DeepSeek 等以“每任务成本”而非榜单分数取胜的厂商形成直接压力。 在针对真实代码库中复杂软件工程任务的 DeepSWE v1.1 上，GPT-6.1 Sol 据称以约五分之一的成本达到 GPT-6 Astra 的水平，同时在更低的推理强度下比 GPT-6 Sol 的最佳成绩高出 6.4%；Artificial Analysis 的第三方评测显示，它在 Intelligence Index 上仅比 Astra 低 1 分，而每任务成本不到后者的四分之一。对反复调用的智能体编程会话而言，幅度的缓存折扣（比标准输入价格低 95%、比 GPT-6 Sol 的缓存价低 50%）或许才是最关键的指标。

## [隐私分析发现网页与移动端 AI 智能体会向追踪器泄露用户提示词](https://jorgegarciaherrero.com/wp-content/interactivos/20260916-Prompt-like-a-butterfly-sting-like-a-tracker-%28clean%29.pdf) ⭐️ 8.0/10

一篇题为《A Privacy Analysis of Web and Mobile Conversational AI Agents》（网页与移动端对话式 AI 智能体的隐私分析）的新论文，对网页端和移动端对话式 AI 智能体进行了对比研究，揭示两者都会把用户的提示词数据泄露给第三方追踪器和平台端点，论文副标题为“像蝴蝶一样输入，像追踪器一样蜇人”。随附的 Hacker News 讨论（408 分、130 条评论）还揭示了一些不为人知的具体行为，例如 ChatGPT 会在用户真正点击发送之前，就把尚未完成的提示词流式传输到 \`conversation/prepare\` 端点。 其重要性在于，对话式 AI 智能体正日益成为人们起草敏感内容（法律、医疗、金融、科研）的界面，而该分析表明，无论用户使用网页端还是移动端，本应私密的提示词都可能流入广告追踪和数据管道。这一议题正处在 AI 产品部署、消费者隐私风险与遥测工程设计三者的交汇点上，对任何上线基于大模型功能的团队都直接相关。 该论文的核心贡献是对网页端与移动端智能体攻击面进行结构化对比，梳理了哪些追踪器会被触发，以及哪些平台 API 或权限会放大暴露面。讨论中提出的一个重要保留意见是：移动端与网页端的差异部分源于平台级 SDK 与权限模型，而非智能体代码本身；此外，把 UUID 放在 URL 里的做法常被误认为真正保护了隐私。

hackernews · damaru2 · 9月29日 09:03 · [社区讨论](https://news.ycombinator.com/item?id=49890226)

**背景**: 对话式 AI 智能体是把远程大语言模型包装起来的聊天前端（网页应用或移动应用）；当你输入提示词时，数据会经过应用自有的后端，往往还会经过应用内嵌的第三方分析、广告或崩溃上报 SDK。第三方追踪器指用于统计分析和广告归因的脚本或 SDK，它们可以观察到请求元数据，有时甚至能看到请求体；而“平台端点”指操作系统或厂商提供的 API，应用必须调用它们，而这些 API 可能记录请求内容。以往针对 AI 聊天产品的隐私研究主要关注提交内容是否被用于模型训练，而这篇论文把注意力转向了模型外围的追踪与遥测层。

**社区讨论**: 评论者大多认为这些发现印证了一个更普遍的模式，而非意外：有人指出 ChatGPT 似乎会把未完成的提示词预先发送到 \`conversation/prepare\` 端点，从而可能刻画用户的写作节奏和想法演变；另有人发现 Perplexity 把 URL 中的 UUID 当作隐私保护，但该链接实际上会暴露整段对话。多位评论者将此与此前“私有 Codex 会话中未发表草稿”的争议联系起来，认为本应私密的提示词和结果不断外泄——要么进入训练数据，要么进入广告追踪管道——这正是支持在本地运行开源模型、彻底绕开应用的有力理由。也有更持怀疑态度的观点指出，移动端的大部分风险可能来自平台 API 与权限层，而非智能体本身；还有评论者用《辛普森一家》的梗调侃，说用户都成了把秘密全盘告诉 Willie 的“Milhouse”。

## [OpenAI 发布 Dots：可常驻后台运行的智能体](https://openai.com/index/introducing-dots/) ⭐️ 8.0/10

OpenAI 正式发布 Dots，这是一款“常驻在线”的智能体产品，被设计为不依赖特定硬件或界面，能够在后台持续运行、在极少人工干预下推进用户设定的目标，而不是被动等待指令。早期报道将其定位为 Meta 的 Muse 智能体的直接竞争对手，该消息也引发了非常热烈的社区讨论（464 分、353 条评论）。 这标志着前沿实验室正从被动响应的聊天助手转向常驻在线、拥有独立沙箱、记忆与深度集成的持久型智能体，这一方向可能显著加深平台锁定效应，并重塑与 Anthropic、Meta 等的竞争格局。开发者和普通用户会通过订阅定价、使用额度限制，以及与 Codex、ChatGPT Work 等既有产品之间日益模糊的重叠，直接感受到其影响。 据早期报道，Dots 被设计为不依赖特定硬件或界面，可在后台持续追求目标，但相关报道并未披露其底层模型、记忆架构与定价细节。此次发布恰逢外界对 OpenAI 人工智能测试安全性的批评再度升温，社区成员也指出 Dots、Codex 与 ChatGPT Work 之间的边界正变得难以区分。

hackernews · alvis · 9月29日 17:07 · [社区讨论](https://news.ycombinator.com/item?id=49896604)

**背景**: 常驻在线智能体与上一代被动响应的“Copilot”式工具不同：它们不等用户发问，而是按计划或触发器运行，持续重算流水线、读取新到的支持工单或检查发票。要让这类智能体 7×24 小时可靠运行，实际需要托管环境、持久记忆、幂等性与可观测性，以避免重复或中断的操作造成破坏。OpenAI 的 Codex 是其用于自动化软件工程任务的 AI 编程智能体套件，而 Meta 的 Muse 则是面向消费者的竞品智能体，因此评论者把 Dots 视为“云端智能体即个人电脑”这场竞赛的一部分。
